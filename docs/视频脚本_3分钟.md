## 一、录前准备（5 分钟）

| 项 | 操作 |
|---|---|
| 清空旧数据 | 打开 `index.html` → 右上角「隐私说明」→「清除本地全部数据」，避免录到上一单档案 |
| 浏览器 | Chrome / Edge，缩放 100%，隐藏书签栏，关闭通知与输入法弹窗 |
| 窗口 | 1920×1080 全屏，或 1600×900 居中（字体更清楚） |
| 演示数据 | 只用内置「演示模式」三案例，**不录真实企业资料** |
| 签字信息 | 审核人填「选品员A」，日期用当天；不要用真实姓名 |
| 录音 | 先单独录口播，再对口型/对齐时间轴；或一次录屏+麦克风 |
| 字幕 | 全部硬字幕，避免方言口音影响理解 |

> 重要：演示案例的生产日期是**打开当天动态生成**的，任何一天录制都不会过期；SC 号与信用代码均为演示虚构值。

## 三、口播逐字稿（可直接照读，约 640 字）

**[0:00–0:15]**
助农直播间里，一个品能不能上播，往往靠经验拍脑袋。可一旦下播、退货、罚款，成本都落在农户身上。

**[0:15–0:35]**
我们做了「上播前·选品体检」，把选品合规拆成六步：分流、资料录入、证据核验、规则判定、人工审核、档案导出。纯前端，双击就能用，资料不出本机。

**[0:35–0:55]**
第一步先分流：产品是食用农产品，主体是农户自销，平台是抖音。类型选错，后面的规则就全错了，所以这一步必须选对。

**[0:55–1:25]**
先看绿色案例，烟台苹果。点「证据核验」，日期和合格证通过；点「规则判定」，判「绿·可播」。没有硬性违规，关键字段齐全，直接给可播结论。

**[1:25–2:10]**
再看黄色案例，莱阳梨膏。包装文案写了“全网最低价、顶级食材”，命中绝对化用语；标签还有缺项。判定是「黄·整改」。点「生成整改单」，它会写清楚：改哪句话、依据哪一条、几天内改完、谁来签收。确认后进入人工审核，签字生效，再导出档案。

**[2:10–2:45]**
红色案例更典型。检测报告上的产品名是“苹果汁饮料”，我们申报的是“莱阳梨膏”。规则判定「红·禁播」——报告对不上，这个品不能播。

**[2:45–3:00]**
最后看规则库：共 21 条，已启用 18 条，未启用的 3 条明确标注。AI 不生成法条、不联网验真，最终结论必须由人选品员签字。

## 四、录制操作清单（按顺序点，不绕路）

1. 首页 → 右上角「演示模式」→「绿·可播（烟台苹果）」
2. 点「证据核验」→ 点「规则判定」→ 停留 2 秒给绿徽标特写
3. 「演示模式」→「黄·整改（莱阳梨膏）」
4. 「证据核验」→「规则判定」→「生成整改单」→ 鼠标划过“替换建议”那一行 →「关闭」
5. 「进入人工审核」→ 两条裁决都选「确认违规」→ 结论选「整改后上播」→ 签字「选品员A」→ 日期当天 →「签字生效」
6. 「导出档案（第 6 步）」→ 展示档案编号与「官方核验」行 →「返回」
7. 「演示模式」→「红·禁播（冒用报告）」→「证据核验」→「规则判定」→ 放大报告产品名不符的提示
8. 「查看规则库」→ 展示“共 21 条 · 已启用 18 条 · 未启用 3 条” →「关闭」

> 若时间超了，优先删第 6 步的档案展示和第 8 步的规则库停留，**不要删红案例**——它是全片最有记忆点的部分。

## 六、翻车备用方案

- **录屏软件崩溃**：改用手机架拍屏幕 + 后期配口播；画面抖动不影响内容分。
- **演示数据被清空**：重新点「演示模式」即可，三案例不依赖网络。
- **时间只剩 2 分钟**：保留 0:00 钩子、黄案例整改单、红案例报告不符、结尾边界四段；绿案例用一张截图带过。
- **评委要求“真实操作”**：不要用剪辑拼接伪造点击；本脚本所有步骤在工具里都可 1:1 复跑。

## 七、口播禁区（避免夸大）

- 不说“AI 自动判定违法”“百分百识别违规”——实际是规则引擎 + 人工签字。
- 不说“已联网核验企业/证书”——实际只做本地结构校验 + 官方入口跳转。
- 不说“覆盖所有食品品类”——当前覆盖四类，3 条规则未启用，如实说。
