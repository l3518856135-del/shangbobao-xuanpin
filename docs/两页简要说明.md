# 上播前·选品体检 —— 两页简要说明

**一句话**：让助农直播的选品员在上播前 3 分钟，查清"这个品能不能播、缺什么、怎么改"。

## 一、真实问题

助农直播基地的选品场景有三个特点：**品类杂**（初级农产品、预包装食品、保健食品、地理标志产品，规则完全不同）、**底子薄**（选品员多无法律背景，靠"听说过"判断）、**证据散**（证照、检测报告、标签信息分散在供应商手里，出事才回头找）。

结果是两类损失同时存在：**该拦的没拦住**（下播、处罚、退货），**不该拦的被拦死**（带泥的萝卜被要求 SC 证）。

## 二、我们的做法

把合规判断拆成一条可复跑的六步流水线：**分流 → 资料录入 → 证据核验 → 规则判定 → 人工审核 → 档案/整改单**。

判定输出四种状态：

| 状态 | 含义 | 处置 |
|---|---|---|
| 红·禁播 | 存在硬性违法/违规事实 | 禁播，不出整改单 |
| 黄·整改 | 整改后可播 | 出整改单，7 日内改完复检 |
| 绿·可播 | 资质齐全有效、宣称合规 | 出档案，可上播 |
| 灰·信息不足 | 资料不全，**不判违规** | 给"缺什么"清单 |

核心设计：**灰态专治误杀**——资料不齐不判违规，只告诉你要补什么。

## 三、凭什么不一样

市面上的工具大多停在"违禁词检测"。我们把差异放在三处：

1. **先分流，再判定**：产品类型前置判断，避免跨类型误判（例如把初级农产品当预包装要求 SC）。
2. **机器查、人签字**：判定只是提示，必须逐条裁决（确认/误报/忽略）并签字才写档；标"误报"的条目沉淀下来，用于后续修订规则。
3. **出可执行产物**：黄态出整改单（改哪、怎么改、依据哪条、几天内、谁签收），绿态出档案（可打印、可脱敏）。

## 四、已经验证到什么程度

- **规则库**：21 条结构化规则（v0.2 修订稿），**18 条已接入引擎**，3 条未启用并在查看页显式标注"未启用"。
- **自测**：48 条用例，**48/48 通过**，含反向用例防误判（"最后一天""第一场直播""非畜禽"等均不误报）。
- **案例**：三组实跑留证——绿（烟台苹果）、黄（莱阳梨膏，出整改单）、红/灰（冒用检测报告、资料缺失）。
- **依据**：已核对原文并留链——广告法 9（三）/17/18 条、食安法 34（八）（十）/35/73/78 条、GB 7718 §4.1.1、GB 28050 第 7 章，以及 **2026-03-20 施行的总局令第 120 号第 16/18/19 条**；其余标【待核对】。

## 五、技术与边界

**技术形态**：纯前端、零后端、零构建，双击 `index.html` 即用；数据只存本机浏览器。仅一个可选的多模态 OCR（未配置密钥则完全离线可用）。

我们不做的三件事，既写进产品文案，也写进说明文档：

- **不生成法条**：依据全部来自人工编审的规则库；USCC 只做校验位实算、SC 只校结构，**不声称联网验真**；
- **不鉴定报告真伪**：只识别"报告与申报品对不上"这一可复核事实；
- **不替人下结论**：AI 语义只提示、不判定，结论须人工签字。

## 六、价值

- **对选品员**：3 分钟出结论，直接知道改哪里，不用翻法条。
- **对基地**：减少下播、退货与重复沟通的损失；档案留痕，可复盘责任链。
- **对监管协同**：档案含规则库版本、依据截至时间、核验结果与审核签字，结论可追溯。

## 七、下一步
