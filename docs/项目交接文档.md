## 3. 选题是怎么定的（决策全过程·防推翻）

> 这段极其重要：接班者如无强证据，**不要重新选方向**。以下每个否定都有理由。

### 3.1 我们把握的三问筛子（评委必问题）

用户在选题阶段提出三个框架问题，成为最终筛选标准：
1. **互动的对象是谁**——目标用户是否明确可达（真会用它的人）
2. **问题小而高频吗**——任务边界小、且高频发生（每天做的琐碎环节＞一季度一次的大事）
3. **AI输出的对错能自证吗**——有没有客观依据可核对（法规条款/规则库/公开算法），还是黑盒判断

### 3.2 被否定的方向（按时间顺序，全部留档）

| 方向 | 层级 | 否定理由 |
|---|---|---|
| 农产品带货话术生成器 | 内容生成 | 同质化极高（90%团队做生成器），价值难量化 |
| 品牌评论智能回复助手 | 内容生成 | 门槛最低、同质化最高，仅作保底 |
| 文旅景区传播内容工坊 | 内容生成 | "排期日历"价值难量化，易被判不聚焦 |
| AI营销质检官（发布前静态检查文案） | 质检 | 被并入更好的方向（见下） |
| AI搜索品牌声量雷达（多模型口碑监测） | 监测 | 新颖且直击评委，但易做成"报告"而非"工具"；当初引用的"AI搜索占位"证据出自**赛道二**条文，证据链有瑕疵 |
| 乡播护航·直播切片合规复盘 | 事后复盘 | ①"实时护航主播"是伪场景（主播没空看）②事后复盘AI判断只有"半自证"③比"事前预防"差一拍 |

### 3.3 为什么最终选「上播前·选品体检」（事前预防·选品风控）

用三问筛子全优通过：
- **对象明确**：助农直播基地选品员/运营——每个基地都有该岗位，选品是上播前必经动作（不开播就没收入，使用有刚性）
- **小而高频**：基地天天开播、天天选品；单次任务=审一个产品的资料包；**事前预防**（选品出事=直播间连带封号）比事后复盘痛点更前置
- **输出可自证**：三条硬依据线——①广告法/食安法条（规则库引用条款原文）②**统一社会信用代码校验位可前端实算**（GB 32100-2015公开算法，100%自证）③SC号结构校验（位数/类别码/区划码）
- **演示有哇点**：现场丢一份**伪造的质检报告**，工具当场识破（编号格式异常+无CMA章）→评委30秒懂价值
- **学校背书**：农业工程学院做助农合规，评委天然相信"学生懂行"
- **山东味**：内置烟台苹果、章丘大葱、德州扒鸡等山东品牌素材

## 4. 产品定义与功能细节

### 4.1 产品一句话

**「上播前·选品体检」——直播营销选品合规决策工具**：开播前把选品资料交给工具，走完"**分流→核验→判定→人审→档案**"五步，拿到带法规依据的红黄绿灰分级卡和整改单。

### 4.2 用户与痛点

- **目标用户**：山东助农直播基地、合作社、农产品电商企业的**选品员与直播运营**（机构侧高频用户；不是农户本人、不是主播本人）
- **核心痛点**：①选品出事直播间连带封号 ②人工排查耗时长（约2小时/次）且不专业 ③判定标准不透明、被处罚后无法应对申诉
- **价值量化口径**：单次体检 2小时→15分钟；拦截带病选品N个/月；供申诉证据链

### 4.3 四个设计红线（不可动摇）

1. **AI禁止生成法条**：所有法规依据只能引用人工编审的规则库，杜绝法条幻觉（评委核出假条款=数据造假=一票否决）
2. **判定可复现**：每条判定必须附法规条款原文+编号+可核对链接，红黄绿灰有明确可复现标准
3. **AI语义只提示不定性**：语义判断一律标"疑似/提示性意见"，最终必须**人工签字生效**
4. **不声称虚假能力**：SC号没有全国统一开放联网验真接口→只做结构校验+一致性交叉+官方入口跳转人工核验；**SC第14位校验码算法未公开，不校验校验位**

### 4.4 判定体系（红黄绿灰）

| 等级 | 定义 | 出档动作 |
|---|---|---|
| 红 RED | 禁播：硬性违法/违规事实（应持证无SC、蓝帽子缺失、疾病治疗宣称、资质过期、冒用地理标志等） | 禁播说明+法条引用 |
| 黄 YELLOW | 整改后可播：待核验/标签缺项/绝对化用语/报告临期/信息不一致 | 整改单：补什么材料+**宣称文案合规替换表述** |
| 绿 GREEN | 可播：类型正确、资质齐全有效、宣称合规、标签完整、官方核验通过 | 通过卡，人工签字生效 |
| 灰 GRAY | 信息不足无法判定（资料缺失≠违规，**不误杀**） | 待补充材料清单 |

### 4.5 产品类型分流（防误判的关键域逻辑）

**必须先选类型再套规则**，否则"带泥的萝卜"会被误判为需SC的预包装食品：

| 类型 | 关键规则 | 资质要点 |
|---|---|---|
| 食用农产品 | 无需SC、不适用预包装标签 | 承诺达标合格证（畜禽加检疫证明） |
| 预包装食品 | SC+GB7718标签+GB28050营养标签（豁免品类除外） | SC证、标签、营养表 |
| 保健食品 | 蓝帽子+注册/备案号；普通食品不得宣称保健功能 | 蓝帽子、注册号、"本品不能代替药物"警示语 |
| 地理标志农产品 | 专用标志须授权、不得冒用 | 使用许可证明、产地一致性 |

销售主体也区分：农户自产自销 / 合作社 / 企业经销（资质要求不同）。

### 4.6 功能清单（8模块，P0必做/P1扩展）

**A 决策向导（P0）**：产品类型4选1 + 销售主体 + 带货平台（MVP只做抖音）→ 明示"本次适用规则线"
**B 资料录入（P0）**：B1多图上传（包装图/质检报告/SC证/营业执照）｜B2 OCR提取关键字段（SC号、统一社会信用代码、报告编号、产品名、生产者、日期）｜B3 **OCR结果回显为可编辑字段，关键字段人工确认后才判定**（防OCR错一位全错）｜B4 纯表单手工录入兜底（纸质件/识别失败/无网）｜B5 脱敏开关（演示模式打码）
**C 证据核验（P0，五步）**：
- C1 结构校验——SC号：长度14、前3位类别码对照《食品生产许可分类目录》32类、中间6位区划码对照行政区划表；**统一社会信用代码：GB 32100-2015 公开加权算法实算第18位校验位**（100%自证的演示硬点）
- C2 一致性交叉——SC类别码vs申报品类；SC地区码vs产地地址；报告产品名/规格vs申报产品
- C3 官方核验辅助——一键跳转市场监管总局政务平台（食品生产许可获证企业查询/特殊食品查询/各省局入口），人工查完勾选"已核验/不符"+传截图
- C4 质检报告核验——CMA/CNAS资质标识；报告产品/规格/生产者与申报一致；结论合格且有效期；委托检验vs型式检验区分；**报告仅限内部审核，不当宣传素材**
- C5 保健食品专项（简化）——蓝帽子+注册备案号存在性

**D 规则引擎（P0，核心）**：详见第5节规则库设计

## 5. 规则库设计（产品的心脏）

### 5.1 双引擎原则

- **RULE引擎**（硬规则）：规则库直接触发，判定100%可复核（依据+触发字段写进档案）
- **AI-SEMANTIC引擎**（语义提示）：大模型判断"疑似命中某条"，只提示不判定，人工终审生效

### 5.2 规则元数据结构（rules.json 字段）

`id`（R-{分类}-{序号}）· `name` · `category`（COM通用/NC食用农产品/YB预包装/BJ保健/DL地理标志）· `platform`（GENERAL法规底线/DOUYIN平台专用）· `trigger`（机器可判定的触发条件）· `level`（RED/YELLOW/GREEN/GRAY）· `engine`（RULE/AI-SEMANTIC）· `basis`（法规名称+条款号+原文摘录）· `link`（法规数据库URL）· `action`（整改动作）· `risk_note` · `updated` · `source`（2026-10-25 起移除 `reviewer` 字段，不再要求填写编审人姓名）

### 5.3 首批20条规则（AI起草，**待人工编审**）

- **通用COM·6条**：R-COM-001疾病治疗/预防宣称（红，广告法17+食安法73）｜R-COM-002非保健食品宣称保健功能（红）｜R-COM-003绝对化用语（黄，广告法9条3项）｜R-COM-004虚构权威背书（黄，广告法28+反不正当竞争法8）｜R-COM-005承诺性效果（黄）｜R-COM-006报告与产品不符（红）
