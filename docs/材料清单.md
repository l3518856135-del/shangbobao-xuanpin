## 一、可运行作品（核心交付）

| 文件 | 说明 |
|---|---|
| `index.html` | 工具入口，双击即可在浏览器打开（纯前端，零后端、零构建、零安装） |
| `styles/main.css` | 界面样式（含打印样式：档案 / 整改单各自独立打印） |
| `js/app.js` | 主流程与界面逻辑（分流→录入→核验→判定→审核→档案/整改单） |
| `js/engine.js` | 规则判定引擎（词表命中 + 字段一致性交叉 + 检测报告比对） |
| `js/validate.js` | 字段校验器（GB 32100 校验位实算、SC 结构、日期/临期） |
| `js/rules-data.js` | 规则库运行时数据（与 `data/rules.json` 同源，供 file:// 双击运行） |
| `data/rules.json` | 规则库权威源（21 条规则结构化，v0.2 修订稿） |

**运行方式**：双击 `index.html`；或 `python -m http.server` 后浏览器访问。

## 五、能力边界与红线（对外统一口径）

1. **AI 不生成法条**：所有法规依据来自人工编审的规则库；条款号未核对完的标【待核对】。
2. **不做联网验真**：统一社会信用代码只做 GB 32100 校验位本地实算；SC 号只做 14 位结构校验，不校验末位、不查库。第 3 步提供官方平台跳转，并在核验卡内记录“一致 / 不符 + 日期”的人工核验留痕，**不自动回填官方结论**。
    - R-YB-003（SC 类别码 × 申报品类）本期**未启用**：32 类分类目录对照表工作量大，转人工核验；规则查看页与技术说明均已明确标注，不做“已全自动识别”的暗示。
3. **报告比对不等于真伪鉴定**：R-COM-006 只识别"报告与申报品不匹配"这一可复核事实，不能证明报告本身是否伪造。
4. **四态不误杀**：信息不足判灰而非判违规；食用农产品不要求 SC。
5. **人工签字生效**：判定结果为提示，最终结论须审核人签字后写档。
6. **数据本地留存**：纯前端本地运行，不上传云端；档案导出支持脱敏。
7. **案例为演示数据**：三份案例的产品/产区取自公开真实品类，**生产主体全部匿名脱敏，证号均为演示虚构值**；判定结论仅演示工具能力，不构成对任何企业或个人的合规认定（详见第三节"案例数据口径"）。
